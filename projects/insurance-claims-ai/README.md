# Insurance Claims AI Pipeline

A production-inspired AI document-processing and validation pipeline for insurance operations.

## What it demonstrates

- Converts unstructured accident-report text into structured claim fields.
- Normalizes and validates extracted values.
- Compares extracted data with an existing claim record.
- Flags mismatches for human review instead of silently accepting AI output.
- Supports an optional OpenAI-powered extraction path while keeping a deterministic local demo.
- Includes tests and a reproducible benchmark for the workflow.

## Problem

Insurance operations teams often spend time reading documents, locating vehicle and accident facts, entering those facts into downstream systems, and checking them against claim records. The bottleneck is not just OCR or text extraction; it is producing trustworthy structured data from inconsistent documents.

## Architecture

```text
Police / Accident Report
          |
          v
   Text / PDF ingestion
          |
          v
   Extraction + normalization
          |
          +------> optional LLM extraction
          |
          v
   Structured claim record
          |
          v
 Validation + mismatch detection
          |
      +---+---+
      |       |
   PASS    REVIEW
              |
        Human analyst
```

## Quick start

```bash
cd projects/insurance-claims-ai
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python demo.py
pytest -q
```

The demo works without an API key.

## Optional LLM mode

Set `OPENAI_API_KEY` and run:

```bash
python demo.py --llm
```

The LLM path is deliberately wrapped behind a small interface so the deterministic validation layer remains independent of the model provider.

## Example output

The demo extracts fields such as:

- VIN
- vehicle make/model
- drivable status
- insured/owner details
- tow location
- impact point

It then compares those values with a reference claim record and reports field-level mismatches.

## Impact evidence

My professional insurance-operations work provided the real-world motivation for this project. I reported approximately **40% reduction in processing time** and **25% reduction in rework/errors** for an AI-assisted workflow. Those production figures are experience-based and are not presented as benchmark results generated by this repository.

This repository provides a separate, reproducible benchmark so a reviewer can run the workflow locally and inspect the underlying calculations.

## Responsible automation

This is a portfolio / engineering demonstration, not a medical, legal, or insurance decision engine. AI output is treated as a proposed extraction and is validated before downstream use. Real customer documents should not be uploaded to a public repository.
